# 蒸留の方法(L1〜L6)

## なぜ層に分けるか

500ページの本を一度に「要約して」と言うと、実際には目次と目立つ見出しから
それらしい文章が作られる。読んでいない箇所が、読んだ顔をして混ざる。
これは要約の失敗というより**出典の失敗**で、後から検証できない。

層に分ける目的は圧縮ではなく、**各段階でどこまで読んだかを固定すること**。
下の層のカバレッジが埋まって初めて上の層に進む。台帳(`analysis/state.json`)が
その順序を機械的に守る。

## 四つの声を混ぜない

どの層の出力でも、次の四つを表記で区別する。混ざると、
本に書いてあったことと、こちらが考えたことの区別がつかなくなる。

| 記号 | 誰の声か | 書いてよいこと |
|---|---|---|
| `【著者】` | 著者の明示的な主張 | 本文に書いてあること。必ず `[scan p.NNNN]` を付ける |
| `【推論】` | こちらの推論 | 本文から導いたが、著者が書いてはいないこと |
| `【評価】` | 批判的評価 | 根拠の強さ、反証、前提の限界、著者の盲点 |
| `【判断】` | 利用者の事業judgment | 國本さんの文脈での意思決定。文脈が無いなら書かない |

`【著者】` にページ番号が無い行は、その時点で信頼できない。
自分の推論を著者の主張として書くのが、この作業で最も避けたい失敗。

## ページの引き方

- スキャン通し番号を `[scan p.0123]` と書く。これが一次の座標系
- 本に印刷されたノンブルは**照合できたときだけ** `[p.111 (scan p.0123)]` と併記する
- PDFの通し番号 = 本のページ番号、と勝手に仮定しない。表紙・扉・折込みでずれる
- 訂正は `analysis/corrections.md` に書く。`text/batches/*.md` は不変層

## L1: バッチカード(40ページ単位)

**入力**: `text/batches/part-NNNN-MMMM.md` 一つ
**出力**: `analysis/l1/part-NNNN-MMMM.md`

OCRバッチを**すべて読んでから**書く。検索で拾って埋めない。
分からない箇所は原本のページ画像に戻って確認する。

```markdown
# part-0041-0080 (scan p.41–80)

## このバッチの位置づけ
【推論】第2章の後半から第3章の冒頭。前バッチの「株主間契約」の議論を受けている。

## 著者の主張
- 【著者】共同創業者が二名以上いる場合、離脱時の株式の取扱いを事前に定めないと
  次の資金調達が止まる [scan p.0050]
  - 著者が挙げた根拠: 自身が扱った複数案件 [scan p.0051]
  - 根拠の種類: 事例(統計・調査の提示はない)

## 定義された用語
- 【著者】創業株主間契約 — 共同創業者の離脱時の株式の扱いを事前に合意しておくもの [scan p.0048]

## 手順・判断基準
- 【著者】業務委託契約は ①知財の帰属 ②再委託の可否 ③解除条項 の順に見る [scan p.0120]

## 数字・図表
- 【著者】図3: 調達ラウンドごとの持分推移 [scan p.0062]

## 著者自身が挙げた限界・例外
- 【著者】日本の非公開会社を前提としている旨の断り [scan p.0055]

## 評価
- 【評価】根拠が著者の経験に閉じており、反証事例の検討がない
- 【評価】社内ベンチャーのように親会社規程が上位にある形態は射程外

## 引っかかり・未解決
- scan p.0067 は表が潰れていて判読できない。原本の確認が要る
```

**空でよい**。そのバッチに主張が無ければ「本バッチは事例の列挙のみ」と書く。
無理に項目を埋めるとノイズが増え、上の層がそれを本物と誤認する。

## L2: 章

**入力**: その章に対応する L1 カード群 + 決定的な箇所は生OCRに戻る
**出力**: `analysis/l2/chapter-NN.md`

章単位で、バッチ境界に切られた議論をつなぎ直す。
L1の連結ではなく、**章の論証を一本に組み直す**。

含めるもの: 章の問い / 主要な主張と根拠 / 手順 / 章内の矛盾 / 前後の章との接続。

## L3: 本の構造

**入力**: L2 すべて
**出力**: `analysis/l3/book-structure.md`

本全体を一つの論証として見る。

- 著者が解こうとしている問題と、その前提
- 主張の依存関係(何が何を支えているか)
- 全体を通じた繰り返し(著者が本当に言いたいこと)
- 扱われていない論点(**書かれていないことの記録**。目次には出ないので、ここでしか残せない)

## L4: 批判的検討

**入力**: L3 + 決定的な主張は生OCRで再確認
**出力**: `analysis/l4/critique.md`

- 根拠の強さの棚卸し(実証 / 事例 / 経験則 / 根拠なし)
- 前提が変わると崩れる主張
- 著者の立場から来る偏り(実務家の経験則を一般則として書いていないか)
- 他書・他の資料と食い違う点
- **この本を使ってはいけない場面**

ここまでは事業文脈なしで書ける。文脈が無いなら L4 で止めて報告する。

## L5: 事業への適用

**入力**: L4 + 利用者から提供された事業文脈
**出力**: `analysis/l5/application.md`

事業文脈が無いまま書かない。文脈を捏造して埋めるくらいなら、
L4で止めて「文脈が要る」と言うほうが有用。

- 【判断】として、どの主張がどの意思決定に効くか
- 効かない/前提が合わない主張は、合わない理由とともに落とす
- **有用な示唆がゼロでもよい**。件数のノルマを置かない。
  弱い関連を水増しすると、後でどれが本物か分からなくなる

## L6: 意思決定

**入力**: L5
**出力**: `analysis/l6/decisions.md`

- 次にとる行動と、その根拠になった主張へのページ参照
- 判断を保留した論点と、保留した理由
- 判断が変わる条件(何が分かったら見直すか)

## 進め方の型

```bash
# 1. いまどこか
python3 <skill>/scripts/distill_state.py status <出力先> --verbose

# 2. 次のユニットを読んで書く(1ユニット = 1往復)

# 3. 書いたら即座に台帳へ
python3 <skill>/scripts/distill_state.py set <出力先> \
  --stage l1_batch_cards --unit part-0041-0080 \
  --status complete --output analysis/l1/part-0041-0080.md

# 4. 層が埋まったら次の層を登録
python3 <skill>/scripts/distill_state.py add-stage <出力先> \
  --stage l2_chapters --units chapter-01 chapter-02 chapter-03
```

**1ユニット書いたら即 `set`**。まとめて処理しようとすると、
途中で切れたときにどこまでやったか分からなくなる。台帳が真実で、記憶は真実ではない。
